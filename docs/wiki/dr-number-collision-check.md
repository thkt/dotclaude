# DR 番号は未マージ PR との衝突を確認してから確定する

## 内容

`skills/dr/scripts/pre-check.ts` が返す DR 番号は、ローカルの `docs/decisions/` を走査した既存最大番号 + 1 でしかなく、まだマージされていない他の PR がすでに同じ番号のファイルを用意している可能性を考慮しない。返り値をそのまま Plan や DR ファイル名に確定する前に、未マージの他 PR が先に同じ番号を使っていないか確認し、使われていれば次の空き番号へ送る。

## 定型手順

1. `pre-check.ts` の出力する `number`/`filename` をそのまま採らず、GitHub 上の未マージ PR が同じ番号の DR ファイルをすでに追加していないか確認する
2. 使用済みなら、その番号は埋まっている前提で次の空き番号を採る (着手時点で次の番号も埋まっていれば、さらにその次へ送る)
3. 確認をすり抜けてマージ後に衝突が判明した場合は、空いている次の番号へ振り直し、`docs/decisions/README.md` の表と本文の両方を新番号に揃える

## 参照コード

- `skills/dr/scripts/pre-check.ts` の `main` (`readdirSync(drDir)` でローカルツリーだけを見て `maxNumber + 1` を次番号とする)

## 根拠

- #491 pre-check の返り値でなく、先行 PR がすでに 0110 を使用中という事実を根拠に 0111 を採った
- #703 Plan が指定した DR-0116 は無関係な先行決定にすでに割り当てられており、実装は衝突を避けて 0117 へ採番し直した
