# 文書の分担

新しく書くことが決まったとき、それをどの文書へ置くかを決める。各文書が守備範囲を分け合い、同じ内容を 2 箇所へ載せない。

| 文書              | 守備範囲                                                       | 寿命                     | 読み手が開く理由           |
| ----------------- | -------------------------------------------------------------- | ------------------------ | -------------------------- |
| `rules/`          | 常に守る言語 / ドメインの指令                                  | 書き換えて育てる         | 何を守るのか               |
| `/dr` の置き場    | 決定の根拠と、検討した代替案                                   | 不変。置き換えは supersede | なぜこの形なのか。覆せるか |
| `CLAUDE.md`       | プロジェクト固有の現在状態と、その理由                         | 書き換えて育てる         | このプロジェクトは何か     |
| `docs/research/` | 観測・比較・未採用案と詳しい根拠 | 原本と対象版・状態を保つ | 何を確認したか |

## ルーティング

1. ルールそのものは `rules/` へ置く。そのルールを選んだ根拠は決定記録へ置く
2. 決定記録は frontmatter に `scope:` を宣言する
3. プロジェクト固有の状態は `CLAUDE.md` へ置く。複数プロジェクトに一般化する状態は決定記録か `rules/` へ昇格する

## 重なったときの扱い

`rules/` と、失効していない決定記録の両方に同じ指令があるのは、2 通りのどちらかを意味する。決定記録が現行 `rules/` の歴史的根拠を記録しているか、両者が乖離して突き合わせが要るか。前者なら相互リンクを張り、後者なら乖離を解消する。

## 読む・残す

原本は対象 repo の `docs/research/`、選択理由は `/dr` の置き場に置く。今の作り方は、コード、テスト、理由を述べるコメント、`rules/` が持つ。入口は README・CLAUDE.md、要求と許可の正本は Issue と合意記録とする。関連文書を実装・評価へ渡し、版が必要なら repo 相対パス・Git blob・開始 commit を使う。版一致は採用や正しさの保証ではない。

判断が固まったときと実装差分が揃ったときに、既存文書への影響を確認する。必要な DR 作成と `rules/` の更新を合意済みの変更範囲へ含め、独立評価で原本・コードと照合する。記録条件を満たさない判断は Issue/PR の説明で足りる。DR は dr の MADR テンプレートを使う。

原本のパス・版・観測日・適用条件・合意状態を保ち、DR から辿れるようにする。未追跡資料や生ログを一括公開せず、共有範囲を確認する。他 repo を題材にした資料は範囲を明記し、自動で他 repo へ移さない。合意の出典が不明な判断を accepted にしない。

この分類・形式は Claude と Codex で共通にする。各ホストの実行方式や配布元を揃える条件ではなく、この repo 内の規約とテンプレートで利用できる。
