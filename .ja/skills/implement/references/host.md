# host での起動

`/implement` の Phase 2 と § 停止した実行の再開が使う、args の書き方と、probe と host の出力の扱い。

## args

args は 1 つの JSON オブジェクトで、Write tool でファイルに書いて `--args-file` で渡す。ファイルなら shell の引用を通らないので、修正依頼の文章に引用符や改行があっても壊れない。`repo` は入れない。`--repo` が渡す。agent 経由の起動では、同じ key に `repo` を足したオブジェクトを Workflow tool に渡す。

| key           | 値                                                 | 入れるとき                          |
| ------------- | -------------------------------------------------- | ----------------------------------- |
| `issue`       | Issue の番号の文字列。`gh issue view` の `number`  | 常に                                |
| `publish`     | 真偽値の `false`                                   | `--no-publish` のとき               |
| `startCommit` | 開始 commit                                        | Phase 1 の手順 5 で参照を選んだとき |
| `reports`     | `[{"path": "<path>", "blob": "<blob>"}]`           | Phase 1 の手順 5 で参照を選んだとき |
| `revision`    | `{"pr": "<PR の URL>", "request": "<修正依頼>"}`   | § 既存 PR の修正のとき              |
| `retry`       | 停止の戻り値の `retry_next`。書き換えずに入れる    | § 停止した実行の再開のとき          |

公開しない起動の args は `{"issue":"123","publish":false}` になる。

## probe の出力

probe は、子 session が利用者の permission の規則の下でコマンドを実行できるかを確かめる。確かめるのは `git status --short` と、check の実行ファイルに `--version` を付けたものである。規則が `Bash(bun run:*)` のように引数まで含む形だと、check は許可されていても `bun --version` は拒まれる。`denied` がその形なら、そのことも人に伝える。

| 出力                                    | 扱い                                                                                                                                                                                       |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `ran` が true                           | Phase 2 の次の手順へ進む                                                                                                                                                                   |
| `ran` が false で、`denied` に項目がある | 起動しない。`denied` を示し、AskUserQuestion で 2 つから選んでもらう。permission の規則でそのコマンドを許可してから probe をやり直すか、この回を § agent 経由の起動で起動するかである     |
| `ran` が false で、`denied` が空         | 起動しない。子 session が始まらなかったか、終わらなかった。`why` を示す。`claude` が PATH に無い、login していない、が主な原因である。直してから probe をやり直すか、この回を § agent 経由の起動で起動するかを AskUserQuestion で選んでもらう |

## host の出力

host は最後に、まとめの行 `claude-run: {...}` を出す。その行の `result` は workflow の戻り値を持つファイルを、`state` は再開に使うファイルを指す。戻り値は出力からではなく、`result` のファイルから読む。出力には log が混ざり、長い戻り値は途中で切れる。

| 出力                                                         | 扱い                                                                                                                                                                         |
| ------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| まとめの行があり、`result` がファイルを指す                  | そのファイルを読み、Phase 3 で扱う。`state` を人に伝える                                                                                                                      |
| まとめの行があり、`result` が null                           | script が例外で終わった。`claude-run: the script threw` の行を示し、起動し直すかを人に尋ねる                                                                                 |
| `usage:` だけを出して終わった                                | host が呼び出しを読めなかった。flag と args のファイルの JSON を確かめ、直して実行し直す                                                                                     |
| `held by the running process <pid>` を出して終わった         | 同じ state を持つ host が動いている。`ps -p <pid>` で確かめる。この session が起動した実行なら、その完了を待つ。そうでなければ、終わらせるかを人に尋ねる                     |
| `claude-run: state <path>` はあるが、まとめの行が無い        | host が途中で終わった。時間切れもここに入る。state は残っている。path を人に伝え、同じ args と `--state "<path>"` で実行し直すかを尋ねる。このときは `retry` を足さない       |
