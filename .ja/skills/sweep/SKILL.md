# /sweep - コードベースの総点検

1 回の実行で見る観点は 1 つにする。差分を観点ごとに分け、人が読める大きさに保つため。

## 入力

| `$ARGUMENTS` | 扱い |
| --- | --- |
| 観点の名前 | その観点で、repo のルートから点検する |
| 観点の名前とパス | その観点で、パスの下だけを点検する |
| 空 | AskUserQuestion で観点を1つ選ばせる |

## 観点

| 観点 | 探すもの | 直し方 |
| --- | --- | --- |
| `async` | ホットパスで、互いに依存しない await を順に待っている箇所 | 並行に実行する。順序に意味がある箇所は直さず、一覧に回す |
| `state` | フラグや真偽値に散らばった、暗黙の状態機械 | 状態と遷移を明示した型にする。矛盾する遷移は直さず、一覧に回す |
| `modules` | 浅いモジュール：インターフェースが広く、中身が薄いもの。消しても何も失われないモジュール。呼び出し側が知っている特殊ケース、順序の規則、検証、導出した値。モジュール自身が導ける引数、全呼び出し元が同じ値を渡す引数、誰も読まない引数 | Ousterhout の原則（deepen modules and simplify interfaces、pull complexity downwards、define errors out of existence）で直す。消すと複雑さが呼び出し側に戻るモジュールは残し、何も失われないものは統合して消す。1つの概念は、それを持つ1つのモジュールに置き、特殊ケースや検証をその中へ引き込む。引数を削り、呼び方を1通りにする。全呼び出し元を新しい形に移し、古い経路は残さず消す |
| `defense` | 境界の内側での再検証、不要な try/catch、1回しか使わない helper、起きそうにないケースへの防御 | 外部の値は、それを持つ境界で1回だけ検証する。内側には型の付いた値を渡す |
| `dead` | 使われていないコード、不要になった後方互換のコード、コードと矛盾する資料 | 消すか、資料をコードに合わせる。外部に公開した API と保存済みのデータの形式は直さず、一覧に回す |
| `tests` | 構造に結合したテスト、モジュールの mock、ロジックを持つテスト、振る舞いを確かめないテスト | 公開 API を通して、利用者から見える振る舞いを確かめる形に直す。mock の代わりに実物の依存を使う。消すのは、そのテストが守る関数を別のテストも呼んでいるときだけ |

## 直すかの判断

候補ごとに、起きる頻度と深刻さを 1〜10 で付ける。

| 条件 | 扱い |
| --- | --- |
| 頻度 × 深刻さが5以上で、振る舞いを変えずに直せる | 直す |
| 頻度 × 深刻さが5未満 | 直さず、一覧に回す |
| 直すと振る舞いが変わる。または公開 API や保存済みのデータに触れる | 直さず、一覧に回す |
| 防御を足したくなった | 足さない。失敗の形、起きる確率、増える複雑さを一覧に書く |

## 手順

1. `.claude/OUTCOME.md` を読み、点検の対象が outcome の範囲に入るかを確かめる。無ければ `/outcome` で stub を作る。
2. 観点の「探すもの」を、対象の全ファイルから探す。広い範囲は Explore の subagent に分ける。
3. 候補ごとに「直すかの判断」を当てる。
4. 直す候補を 1 つずつ直し、そのたびにテストを実行する。テストが落ちたら、その修正を戻して一覧に回す。
5. すべての候補が「直したもの」か「一覧」のどちらかに入ったら、出力の形で返して終える。

## 出力

| 節 | 中身 |
| --- | --- |
| 直したもの | file:line、何を直したか、実行したテストとその結果 |
| 一覧 | file:line、問題、頻度 × 深刻さ、直さなかった理由 |
| 見なかったもの | 対象から外したファイルと、その理由 |
