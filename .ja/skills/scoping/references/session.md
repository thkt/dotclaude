# 根拠の保存と引き継ぎ

要求と合意は Issue・下書きから辿り、再利用する根拠だけを Git 管理の文書へ残す。

wiki は現在の知識、decisions は重要な判断理由、research は原本として、`${CLAUDE_SKILL_DIR}/../../rules/conventions/DOCUMENTS.md` の分担に従う。原本だけを増やして、現在の説明を古いままにしない。

報告の要否と、要求の引き継ぎは別に判断する。誰がどの対象・範囲を合意したか、既存の根拠を再利用できる条件と今回固有の条件を、Issue から辿れるようにする。未実施の評価や提案を合意済みとして渡さない。

## 保存と改訂

Issue の記述と出典リンクで足りるなら報告を作らない。再利用する根拠や長い検証結果が必要な場合は、対象 repo の docs/research/へ直接保存・改訂する。問い、出典と対象版・確認日、結論、適用条件、合意状態、未確認事項を必要な範囲で記す。観測した事実、合意済みの規則、提案・仮説を区別し、既存の記載で足りる部分は参照する。

保存前に対象 checkout・保存先・既存内容・差分・共有範囲を確認し、他担当の変更を上書きしない。同じ調査は既存ファイルを改訂する。新規報告は内容を表す Markdown 名にし、README.md は入口用に保つ。Git で無視されず、symlink で別の保存先を指さない通常ファイルとして保存する。内部評価・会話全文・秘密情報・生ログ・ローカル専用パスを取り込まない。

改訂は Git 差分でレビューし、出典・版・適用条件の変更が判断へ与える影響を確認する。人向け文書の事実・数量・条件・範囲・参照を原資料と照合し、既存の独立評価へ含める。

## 調査成果の引き継ぎ

共有担当は差分と公開範囲を確認し、対象 repo の検証・独立評価を経た通常の変更や PR へ必要な報告を含める。既存の調査はコミット済み記録を参照し、生ログを一括追加しない。

対象 Issue、必要な報告の repo 相対パス・確認済みの Git blob ID・開始 commit、保存・commit・共有の状態を揃える。必要な報告がなければその判断を明示する。共有済みなら、報告パス・commit・公開先を Issue から辿れるようにし、未共有なら残る操作を示す。ローカル保存や commit だけで共有完了としない。

会話にだけ残る重要な判断根拠を Issue へ反映する。関連する wiki・判断記録・調査原本は必要な範囲で選び、確認済みの版と今回の要求との関係を引き継ぐ。

実装・独立評価では同じ報告版を参照し、現在のコードへの適用性と矛盾を別々に判断する。参照の一致だけで内容・合意・共有状態を保証しない。報告を更新したら古い評価を流用しない。

実装前の開始条件は `/implement` の Phase 1 が照合する。確認済みの報告が開始 commit に揃わない場合は、引き継ぎ未完了とする。

必要な報告は既存の許可範囲で commit に含める。許可がない操作は保留し、未追跡ファイルを一括追加・削除しない。公開だけが未許可なら、許可済みの実装は `/implement` の `--no-publish` で進められる。
