# /in-your-own-words - 作業の前に、利用者の目的を言い直す

利用者の目的と、利用者が解こうとしている問題を、自分の言葉で言い直す。利用者はそれを読んで、意図が伝わったかを確かめる。

## 手順

1. 目的を 1〜2 文で書く。利用者の指示の言い換えではなく、作業が終わったときに何がどうなっているかを書く。
2. 問題を 1〜2 文で書く。今その状態にない理由を書く。
3. 利用者が言っていないのに推測で補った点を、推測と書き、その根拠を添える。
4. 作業を始めず、続けもしない。言い直しの後に、違う点を直してほしいと頼んでこのターンを終える。

## 例

| 判定 | 言い直し |
| --- | --- |
| Bad | 「#924 の conflict を直したいということですね」。指示を言い換えただけで、目的と問題が無い |
| Good | 「目的: この Mac で `bun install` を速くすること。問題: `globalStore` が無効なので、worktree ごとにパッケージを複写している。推測: 『直そう』を速さの話と読んだ。直前に『install は速くならない』と私が書いたためである」 |
